# Наблюдаемый REST-контракт ЕАЭС

Проверено 30 сентября 2026 года небольшими публичными `POST`-запросами. Исходная [справка REST API](https://opendata.eaeunion.org/opendata/ru/api/restapi) содержит примеры, но некоторые из них расходятся с живым поведением. Адрес и имя коллекции нужно брать из вкладки «Карточка ресурса» нужного реестра либо тематической страницы API; полного опубликованного каталога имён `collection` не обнаружено.

Для [Единого реестра органов по оценке соответствия](https://tech.eaeunion.org/tech/ru/registers/36) опубликованы адрес `https://tech.eaeunion.org/spd/find` и коллекция `kbdread.service-prop-36-v_conformityAssessmentBodyInformationDetailsType_organization_table`. Запрос выполняется методом `POST` с `Content-Type: text/plain` и JSON-фильтром в теле; `{}` означает отсутствие фильтра. `collection`, `limit`, `skip`, `fields`, `sort`, `skipCount` передаются в URL. `fields` и `sort` — JSON-объекты, кодируемые как значения URL-параметров.

Ответ имеет `Content-Type: application/json`. Верхний уровень содержит массив `result` и числовой `responseSize`. При обычном запросе также возвращаются числовые `totalDocuments` и `matchedDocuments`. При `skipCount=true` оба счётчика отсутствуют. При смещении за конец массива `result` пуст, `responseSize=0`, счётчики остаются. Поля документов могут быть вложенными объектами и массивами; их форму общий клиент не изменяет.

На целевой коллекции проверены `limit`, `skip`, проекция через `fields`, многополевая сортировка, `skipCount`, равенство, `$in`, `$and`, `$or` и `$regex`. Значение `limit=0` вернуло весь реестр (на момент проверки 3229 документов). При проекции одного поля `limit=1001` вернул 1001 документ без авторизации. Это расходится с указанными в справке лимитами 500/1000. Клиент требует положительный размер страницы и по умолчанию запрашивает не более 500 записей; на большее количество нельзя полагаться без проверки конкретного ресурса. Число записей и их порядок со временем меняются.

Публичный пример `db1.goodscollection_prod` на `goszakupki.eaeunion.org/spd/find` вернул HTTP 500 с текстом об отсутствии прав или конфигурации коллекции. [Тематическая страница API госзакупок](https://goszakupki.eaeunion.org/erpt/ru/registers/api) вместо него публикует работающие `erpt.v_goodscollection_prod_public`, `erpt.v_RegisterOfWithdrawalNotifications_public`, `erpt.v_databasesection_public` и `erpt.v_RegisterOfManufacturers_publish`. Все четыре подтвердили HTTP 200 при `limit=1` через один `/spd/find`.

Для авторизованного доступа справка описывает получение OAuth-токена через `POST https://opendata.eaeunion.org/auth/realms/eec/protocol/openid-connect/token` с `grant_type=client_credentials`. Для расширенных данных описан отдельный токен групповых политик через `https://opendata.eaeunion.org/idp/request/sendJson?sync=true`, маршрут `platform_svc` → `/token/login_by_token`, затем шлюзовый запрос к `serviceKey=spd` и маршруту `/find`. Внешний HTTP 200 от шлюза не доказывает успех вложенного запроса: нужно проверить внутренние статус и тело. Учётные данные не предоставлялись, поэтому этот путь подтверждён документацией, но не живым запросом. Точный способ обычного прямого авторизованного чтения также не подтверждён.

Справка перечисляет 200, 400, 404, 413, 500, а для авторизованного доступа ещё 401. В ней же 500 может означать недостаток прав. Не повторять его автоматически. Счётчики — свойства отдельного запроса, а не стабильный снимок реестра. Offset-пагинация при изменяющихся данных не гарантирует отсутствие пропусков или дублей; для выгрузки требуется стабильная сортировка по уникальному ключу, если ресурс её поддерживает.

Фикстуры в `testdata` синтетические: они сохраняют форму проверенных ответов, но не содержат имён и контактов из реестра.
