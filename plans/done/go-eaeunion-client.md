## Что мы делаем?

Создаём универсальную Go-библиотеку чтения коллекций REST API ЕАЭС: получение страницы, фильтрация, проекция полей, сортировка, обход страниц и авторизация. Адрес точки входа задаётся один раз в клиенте; в каждом запросе пользователь передаёт имя коллекции, фильтр и параметры выборки. Библиотека возвращает исходный JSON либо декодирует его в пользовательские структуры. Корневой пакет `eaeunion` содержит только общий клиент. Типизированная обёртка `conformity` реализуется следующим отдельным планом в том же Go-модуле: [реестр органов по оценке соответствия](conformity-registry-wrapper.md). Зависимость направлена от обёртки к общему клиенту; общий пакет ничего не знает о реестрах.

Первый потребитель — обёртка Единого реестра органов по оценке соответствия ЕАЭС. Проверенные адрес и коллекция могут использоваться как внешние параметры интеграционных тестов общего клиента, но не становятся его встроенными константами, типами или фильтрами. Проверка 30.09.2026 подтвердила анонимное чтение через `https://tech.eaeunion.org/spd/find` из коллекции `kbdread.service-prop-36-v_conformityAssessmentBodyInformationDetailsType_organization_table`: HTTP 200, JSON с одним элементом `result` при `limit=1`. Предметные результаты исследования перенесены в план обёртки.

Предлагаемая основа — стандартная библиотека Go (`net/http`, `encoding/json`, `net/url`, `context`), без драйвера MongoDB. «Любая коллекция» означает коллекцию с совместимым REST-контрактом и необходимыми правами доступа. OData, поиск коллекций через внутренние API сайта, запись данных, локальная БД и CLI не входят в эту работу.

Реализация завершена в модуле `github.com/ReanSn0w/go-eaeunion-api` (Go 1.23+). Анонимное чтение проверено живым запросом; авторизация проверена локальными тестами без учётных данных.

Источник: [документация REST API ЕАЭС](https://opendata.eaeunion.org/opendata/ru/api/restapi), прочитаны все 28 разделов 30.09.2026. Запросы чтения используют POST, JSON-фильтр в теле с `Content-Type: text/plain` и параметры `collection`, `limit`, `skip`, `sort`, `fields`, `skipCount` в URL. Адрес конкретного API берётся из карточки ресурса. Раздел авторизации уточняет лимиты: 500 записей анонимно, 1000 с авторизацией. Описаны `totalDocuments` и `matchedDocuments`.

После отдельной проверки рубрики «Запросы REST API» архитектура упрощена: её примеры обращаются к одной точке `https://goszakupki.eaeunion.org/spd/find`, коллекция выбирается параметром `collection`. Отдельные URL или адаптеры для каждого реестра не нужны. Все эти примеры используют `db1.goodscollection_prod`; они не подтверждают доступность всех коллекций через этот домен. На иллюстрации синтаксиса сервер и имя REST-сервиса показаны переменными. Поэтому точка входа настраивается на уровне клиента, а доступность разных коллекций через неё проверяется отдельно.

В примерах есть расхождения: `$skipCount` в тексте против `skipCount` в URL, `$or` вместо `$and`, некорректный JSON для `$regex`. Поэтому примеры не считаем готовой спецификацией. Авторизация описывает Client Credentials, дополнительный токен групповых политик и шлюз `/idp/request/sendJson?sync=true`; точный путь обычного авторизованного доступа требует проверки.

Проверка 30.09.2026: POST с телом `{}` к `https://goszakupki.eaeunion.org/spd/find?collection=db1.goodscollection_prod&limit=1` вернул HTTP 500 и текст «Недостаточно прав для выполнения операции или отсутствует конфигурация для запрошенной коллекции». Этот пример общей справки не использовать как рабочую коллекцию по умолчанию.

При дальнейшем исследовании найдена [отдельная страница API госзакупок](https://goszakupki.eaeunion.org/erpt/ru/registers/api), доступная по кнопке API в реестре товаров. Она публикует четыре коллекции и отдельные PDF-спецификации:

| Ресурс | Коллекция |
| --- | --- |
| Промышленные товары | `erpt.v_goodscollection_prod_public` |
| Уведомления об изъятиях | `erpt.v_RegisterOfWithdrawalNotifications_public` |
| Условия производства | `erpt.v_databasesection_public` |
| Карта производителей | `erpt.v_RegisterOfManufacturers_publish` |

Для каждой выполнен анонимный POST с телом `{}` и `limit=1` через один адрес `https://goszakupki.eaeunion.org/spd/find`. Все четыре запроса вернули HTTP 200, JSON с массивом `result` из одного объекта и числовыми полями `totalDocuments`, `matchedDocuments`, `responseSize`. Формат пустой выборки и отсутствие счётчиков ещё не проверены. Авторизованные сценарии вживую не проверены.

Единого документированного метода перечисления всех REST-коллекций пока не найдено. [Каталог ресурсов портала](https://opendata.eaeunion.org/opendata/ru/resourses) содержит ссылки на пользовательские реестры, а технические имена нужно искать в их разделах API или карточках. Эти источники неоднородны: [карточка реестра уполномоченных экономических операторов](https://customs.eaeunion.org/customs_cooperation/ru/registers/authorized_economic_operators), указанная в общей REST-справке, сейчас публикует только OData-ссылку `https://customs.eaeunion.org/odata/Op_12_1_registerAEODetailsType`. Имя OData-набора нельзя автоматически считать именем REST-коллекции. Найденные четыре коллекции — проверенный начальный набор, а не полный каталог ЕАЭС.

    Не собирать всю коллекцию в память автоматически. Для воспроизводимого обхода вызывающий код задаёт стабильную сортировку с уникальным дополнительным ключом, если ресурс её поддерживает. Offset-пагинация при изменении данных не гарантирует снимок без пропусков и повторов; счётчики также могут изменяться. HTTP 500 не считать автоматически временной ошибкой.
